# Cliptric

A local video workspace built with Next.js, TypeScript, FastAPI, and FFmpeg.

## Start Cliptric on Windows

For a new PC, complete [Windows setup](#setup-on-windows) and [Caddy setup](#private-hosting-at-cliptriccom) first. To start the full app, open **three PowerShell windows**. Run each block in its own window from the Cliptric repository root. For this checkout, run `cd C:\Users\josep\projects\cliptric` in each window.

### 1. Start the backend

```powershell
if (-not $env:CLIPPING_FFMPEG) {
    $env:CLIPPING_FFMPEG = [Environment]::GetEnvironmentVariable('CLIPPING_FFMPEG', 'User')
}
if (-not $env:CLIPPING_FFPROBE) {
    $env:CLIPPING_FFPROBE = [Environment]::GetEnvironmentVariable('CLIPPING_FFPROBE', 'User')
}
npm.cmd run api:private
```

Wait for `Application startup complete`. Restart this process after editing `backend/.env`.

### 2. Start the frontend

```powershell
npm.cmd run build  # Run before the first start and after frontend or dependency changes.
npm.cmd run start
```

On a routine restart, run only `npm.cmd run start` to reuse the existing build. Wait for Next.js to report `Ready`.

### 3. Start Caddy for cliptric.com

```powershell
.\.tools\caddy\caddy.exe run --config .\hosting\Caddyfile --envfile .\hosting\.env.private
```

Keep the three windows open and the PC awake while serving [cliptric.com](https://cliptric.com). For local use, the backend and frontend are enough. Open [the local workspace](http://127.0.0.1:3000), or use [local Accounts](http://127.0.0.1:3000/connections) when connecting YouTube. To stop the app, press **Ctrl+C** in each running window.

## Overview

Import a recording, transcribe English speech locally, optionally find AI-suggested moments, review and correct timed words, and export a captioned 1080 x 1920 H.264/AAC MP4. The workspace includes fit/crop and webcam/gameplay framing, saved selections, three caption positions, cancellable processing, paginated history, and interrupted-job recovery. Each captioned export retains its exact transcript revision and word snapshot.

Highlight analysis is opt-in and sends saved transcript text and source timestamps to OpenAI. Video/audio stay local. It needs a backend API key and separately billed API usage; manual selection, transcription, and export remain usable without a key. Campaign checks, multilingual transcription, and a general timeline editor remain later milestones.

## AI prompt settings

Open **Settings** in the sidebar (`/settings`) to edit the instructions for long-form discovery and editorial review, supplied-video review and highlights, clip titles, descriptions/hashtags, caption emphasis, and shared project guidance. Each prompt has its own editor and **Save** control. **Restore default** loads the built-in text into the editor; save to apply it. Navigation warns before discarding drafts.

Overrides persist locally in SQLite and apply to future OpenAI requests without restarting the backend. Existing clips, exports and saved analysis remain intact. Highlight prompt or shared-guidance changes invalidate analysis-cache identity for new requests. Saved project-specific instructions and runtime transcript/context inputs are supplied separately; these are not global prompt templates. Settings do not change API keys, model configuration or sharing/publishing consent.

Fixed application rules are displayed separately and appended to requests. Structured JSON schemas, source/timestamp validation and explicit consent remain enforced by code. Conflicting prompt instructions can still cause rejected model output; review generated results. Saving waits until queued/active project processing and highlight analysis finish or are cancelled, so a multi-request job uses consistent prompts. Concurrent edits require reloading settings before saving. Each prompt is limited to 12,000 characters and 14,000 encoded UTF-8 bytes; invalid edits leave saved values intact. The settings API is `GET/PATCH /api/settings/prompts`; updates contain an allowlisted `key`, current `revision`, and nonempty `prompt`, protected by the existing local API host/origin and request-size controls.

Uploads are saved before opening `/projects/new/{recordingId}` and retain local playback and the thumbnail filmstrip. Analysis range has time readouts instead of duplicate numeric inputs. It controls where AI searches, independently of each clip's duration. Link setup shows an available source thumbnail until the local video is ready; it then switches to playback and extracted frames without losing settings.

`/projects` is the saved-project library; `/projects/{id}` contains results. The existing individual clip studio moved to `/studio`. Recent sources can be reused from home. Older imports remain available through the studio's paginated library and **Create project from this video**, without reuploading footage.

YouTube uses pinned [yt-dlp](https://github.com/yt-dlp/yt-dlp) `2026.10.26` and its matching `yt-dlp-ejs` `0.8.0`, with the installed Node.js runtime. It imports a single public HTTPS video, including standard watch, short, and youtu.be links. URLs are canonicalized to a video ID; playlists and arbitrary remote destinations are not imported. Authentication/browser cookies, plugins, remote component downloads, and access-restriction/DRM workarounds are disabled. A dedicated transport checks every initial/redirected destination against YouTube/Google media domains and rejects non-public DNS addresses; TLS verification remains enabled and inherited proxies are ignored. This is an application network policy, not an OS sandbox.

One YouTube import runs at a time in a disposable worker with visible byte progress, cancellation, a 30-minute deadline, disk reserve checks, bounded files/logs, and the same configured size cap (20 GiB by default) and six-hour source limit as uploads. It selects available H.264/AAC HTTPS media up to 1080p/60 fps. English audio takes priority over unknown-language tracks and dubbed tracks, with yt-dlp's original/default preference ahead of bitrate and non-DRC audio preferred within that language. Known non-English-only audio is unsupported in this English transcription release. Unsupported/restricted/live sources fail with upload guidance. Separate video/audio streams are muxed by a cancellable local FFmpeg process. Remote URLs never enter FFmpeg. Completed imports made with the current audio-selection version are reused; reimporting a legacy link downloads a fresh source once, preserving existing recordings/projects. Interruption never silently retries the download. Credentials, signed media URLs, and provider diagnostics are not copied into UI errors or logs. Uploaded source files still use the existing streaming import route.

YouTube metadata lookup uses the same guarded disposable worker without invoking its media downloader, bounded to one lookup at a time and 60 seconds. Preview records survive restart; thumbnails load from a canonical YouTube image URL derived from the validated video ID. Downloads revalidate the actual media. Up to one second of metadata rounding is allowed and the effective AI interval is bounded to the probed duration; a larger duration mismatch stops generation with setup guidance. Local thumbnails are cached at six bounded source positions, with at most two extraction workers and duplicate-frame reuse. Local playback depends on the source codec's browser support; clipping can still proceed from thumbnails.

## Long-form AI selection

After transcription, Cliptric scans the entire selected range in three-minute discovery windows with 30 seconds of overlap. The maximum clip duration does not expand the window. Windows can grow to accommodate a long minimum clip duration or to cover a long recording within the discovery request budget. Each window can return up to five leads with real segment IDs and exact evidence. Gameplay guidance looks for distinct brief reactions, reversals and exchanges and identifies context that needs footage review. Discovery uses transcript evidence only. The backend validates source timing, duration and exclusions, then removes identical intervals and fuzzy duplicates. `CLIPPING_HIGHLIGHT_DUPLICATE_IOU` (default `0.65`) and `CLIPPING_HIGHLIGHT_DUPLICATE_EVIDENCE` (default `0.5`) control fuzzy matches. Both thresholds must be greater than zero and at most one. Shorter windows can increase the number of billed discovery requests.

If valid leads remain, one global editorial request compares up to 24 options with up to 30 seconds of nearby speech on each side, capped at 96 KiB of option data. The shortlist takes ranked leads from across the timeline. Each option includes the original cut’s segment IDs when they match the source boundaries. The reviewer checks each lead for a hook, enough context, and a supported payoff. It can keep brief complete exchanges or refine a cut using adjacent transcript segments. The requested count guides coverage and limits visible suggestions. The backend validates intervals, removes duplicates, and saves up to 20 reviewed results for reuse. In Quality mode, 3 out of 5 means a dimension works for a new viewer, and every dimension must reach that score. The score is `5 * (hook + context + payoff + standalone)`. Both stages use the existing transcript-sharing consent and editable prompts in Settings. Saved custom prompt overrides remain in effect.

For reviewed cuts in Quality mode, the backend extracts the opening and closing quotations directly from the chosen transcript segments. The reviewer’s main evidence quote must still appear verbatim within the selected interval.

Empty discovery skips review. An empty, valid editorial response means no clips passed review. Invalid output, provider errors and cancellations are reported as distinct unsuccessful attempts and cannot publish discovery leads. On **Retry highlight analysis** or an explicitly approved project retry, matching completed discovery is reused. **Regenerate** deliberately reruns both stages. Failed or incomplete discovery can require its window requests again. The app records each attempt before dispatch and applies existing deadlines, cancellation and saved transcript revision checks.

The `transcript-highlights-v9-editorial` cache version prevents legacy selection results from satisfying new requests. Earlier projects, selections, and exports remain accessible. Cliptric stores one completed discovery snapshot per recording. It reuses the snapshot for matching transcript revisions, ranges, exclusions, project instructions, discovery prompts and model configuration. Changes to the review prompt invalidate final results while retaining compatible discovery. Supplied-video keep/trim and multi-highlight modes retain one request per source, and manual selection remains available.

Long-form Create discloses the additional transcript-sharing/API usage; bulk creation requires its separate unchecked sharing consent when posting copy is enabled. Turning it off retains the local workflow. Existing projects remain unchanged and can use **Description & tags** on individual clip cards.

The adapted copywriting brief is in `backend/social_copy.py`. Copy uses only speech retained in the selected clip (after accepted pacing removals) and saved project instructions, with no claim to have watched footage. It favors short natural hooks, supported keywords and 3-5 relevant tags, avoids generic reach/trend tags unless explicitly requested, preserves punchlines where appropriate, and avoids manufactured controversy, invented visuals, identities, outcomes or performance predictions. It follows the source language unless project instructions request another. Structured output has bounded fields, four distinct options and a source quote checked against the supplied speech. Fewer tags are allowed when context is limited. Sparse/missing speech prompts manual editing instead of a paid request or invented context. Evidence checks and prompts cannot establish factual correctness; review the actual clip and generated text.

Each project item stores its generated options, selected/manual posting text, source/transcript/revision/interval identity, usage and request outcome. Description/tag edits do not render video or change burned-in captions, headlines, Posted state, accounts or approvals. Source intervals/transcripts remain immutable; title/font-only changes preserve posting copy. Finding another batch inherits the project's enabled setting under the existing sharing approval.

Generation records an attempt before dispatch. Ordinary Resume never repeats completed, failed or uncertain copy calls. Existing clips require explicit per-request sharing/billing consent, UUID request identity and a current item revision. Replaying any saved request token is idempotent; retries after an uncertain connection reuse the token, while a new paid attempt is explicit. The per-clip ledger holds at most 64 attempts and never evicts tokens to permit accidental reuse. Manual requests are concurrency bounded, deletion is rejected during active copy generation, and clip changes during inference prevent publishing a mismatched result. Errors remain visible without discarding otherwise usable exports. The existing backend provider/key is reused; no new credential setup or client-side secret is introduced.

YouTube preloads the saved text, and TikTok, Instagram, X and Facebook offer **Use saved description and hashtags** on demand. The handoff resolves the exact current export and refuses stale text. ## Projects: create and deliver a batch

Start on the home page, then name the project and set the analysis range, captions/framing, and clip cap on its setup page. Click **Create clips** to save the project before background processing begins and open the project library. You can navigate away after saving while the backend remains running.

- **Auto** is the default. AI selects natural source-grounded moments of varying lengths from eight seconds up to the selected source range, using bounded overlapping windows of up to ten minutes, without padding to a target. **Manual** sets minimum/maximum bounds from 8 seconds up to the six-hour source bound. The analysis interval is independent of each clip's length; no transcript text outside it is sent for selection. Incomplete boundary words are omitted rather than assigned invented timing. Fewer clips or an empty result are valid.
- The library shows source thumbnails, titles, creation dates, status, clip counts, and a live progress bar for active projects. Results pages also show progress. Progress allocates one quarter to each stage (download, transcription, AI windows, renders) and uses reported bytes, transcription progress, completed windows, and completed exports within each stage. It is workflow progress, not a time estimate; an unknown download size stays at the stage start while showing downloaded bytes. Existing recordings skip download. A separate results page restores settings and clip cards. Saved settings are fixed: create another project to change the analysis interval or generation rules without replacing reviewed clips.
- Up to eight projects can be scheduled, with one project pipeline and one export worker active at a time. Each project selects at most 20 clips. Transcription is reused when available; selection uses the existing revision/settings-aware cache. Status exposes real transcription progress, completed AI windows, and the current render. The existing manual studio remains available.
- Choose **Impact** (bold outlined text with an entrance pop), **Studio** (violet-backed text with a synchronized fade), **Focus** (cyan active-word emphasis), **Flow**, **Glow**, or no captions using keyboard-accessible example cards. Motion previews respect reduced-motion preferences; actual exports use saved word timings. Impact is the new setup/manual-draft default. Classic/Bold/Boxed remain readable for saved projects, style-library entries and immutable exports; only an already-selected legacy style is exposed as such in the picker. Each clip can override styling and emphasis words.
- Caption position supports **Auto**, Lower, Centre and Upper. Optional filler removal targets saved exact “um”/“uh” words, skipping overlapping-neighbor speech. Review every proposal: recognition and silence detection do not determine whether a pause or filler is intentional. Repeated phrases and semantic rewrites are not removed.

Analysis returns proposals without changing media. **Stage proposed edit plan** replaces the editor's current plan; each removal has an enable/restore checkbox and **Restore all removed intervals**. Saving creates a new immutable export. Source-relative removals are limited to 40, must not overlap, must leave no fragments below 20 ms, and must retain at least half the selection and 0.1 seconds. Oversized/invalid combined proposals are shown disabled rather than applied. Word-safe boundary suggestions can expand to saved word edges with bounded padding; accepting them explicitly clears the old edit plan. Reanalyze after changing trim bounds. Source media, original ASR, other clips, prior exports, and exact-export publication approvals are preserved.

Video retains source frames with continuously remapped PTS, rather than concatenating independently rounded video segments. Audio is trimmed/concatenated to sample-exact retained intervals, with short de-click fades around internal edits. The same retained-interval map rebases caption words, clip-relative text overlays, and framing points. Headline timing remains opening-relative to the shortened output. Post-edit placement collisions and overlays that would disappear/become too short are rejected; adjust their timing or restore source intervals. Output duration is verified against the retained intervals, and clip cards show actual exported duration. Restore operations regenerate from the source, never from a previously compressed clip.

**Visual proposals:** Choose conservative face or motion tracking, optionally protecting up to four source regions through the API (the UI exposes one editable HUD/context region). OpenCV's pinned local frontal-face cascade or frame-difference motion detector examines bounded 2 fps samples with a maximum dimension of 320 pixels. The planner retains all detected targets/protected regions, adds context margins, smooths positions, limits panning, validates a simplified path of at most 24 keyframes against every sampled observation, and uses full-picture blur-filled fit when a stable safe crop cannot be established. Crop size remains fixed to avoid zoom pumping; source-coordinate snapshots account for display orientation. Protected regions are checked again after pixel alignment. Existing manual webcam/gameplay split layouts remain available and cannot be combined with a full-frame smart crop.

Face detection is not active-speaker identification. Motion is not semantic gameplay/action understanding. Small/occluded/profile faces, fast unsampled action, and scene changes can be missed; full-picture fallback is a deliberate safety result. Review faces, HUDs, captions, and overlays in actual output. This implementation does not claim active-speaker diarization, automatic scene-based multicamera switching, or content-aware caption relocation. A human-edited reference set and representative playback review are still needed to judge professional output quality.

API/storage: `POST /api/recordings/{id}/quality-plan` accepts `{start,end,transcription_id?,revision?,silence,fillers,threshold_db,minimum_pause,keep_pause,detector,protected_regions}`. Saved transcript ownership/revision is checked before and after analysis. Speech-edit analysis caps the selected/context transcript at 3,000 words. The response includes source-relative `removals`, `retained_intervals`, estimated `output_duration`, suggested source boundaries, warnings, and optional `smart_framing`. Additive SQLite schema version 6 records immutable export-quality snapshots. Owned scratch files are removed on normal completion/failure and explicitly recovered after interruption; unexpected recovery files/links fail visibly rather than being recursively deleted. Backend requirements pin OpenCV and NumPy; install the updated lock before restarting the API.

## Animated captions and word emphasis

**Flow** keeps a readable phrase on screen and highlights the currently spoken word in yellow with a short colour transition. **Glow** adds a soft violet outline/glow to the currently spoken word. Both effects are burned into the downloaded video using FFmpeg/libass; they are not just browser preview effects. Existing static presets remain available.

In project setup or a clip's **More / Edit details** form, optionally enter comma-separated **Words to emphasize**. Matching words become bold with the preset's accent colour; surrounding punctuation and case are ignored. Choose up to 20 words, at most 48 characters each. Matches within a multiword transcript correction are supported, while its original timing remains intact. Words absent from the transcript do not add speech or text. Importance is chosen by the user, without another AI request.

Project defaults and per-clip overrides persist in the saved project and immutable export caption options as `emphasis_words` (default `[]`). `caption_preset` accepts `flow`/`glow` alongside the earlier values; export `captions.preset` accepts them too. Existing records need no database migration. Changing a clip's style or emphasis rerenders only that clip with the saved transcript; existing exports, other clips, and reviewed media remain available. Opening an old export still shows its original static captions.

Animation uses original word intervals intersected with the clip, partitioned around actual starts/ends and pauses. Simultaneous words can be highlighted together. ASS timing rounds inward to centiseconds: a sub-centisecond word remains in the readable phrase without an invented highlight interval; an unrenderably short whole phrase still fails visibly. Animated output is limited to 5,000 subtitle events per export. Text escaping precedes font fitting, and user text never becomes executable subtitle markup. See [ASS transform/blur documentation](https://aegisub.org/docs/latest/ass_tags/).

After updating the backend, restart the API in your own terminal. ## Blur fill in exported clips

Fit mode (`pad` in the API for compatibility) keeps the foreground sharp and fills unused space with a scaled, cropped, blurred copy of the video. Centre-crop mode fills the canvas directly. The renderer adds no black letterbox/pillarbox padding. Captions are applied after compositing and remain sharp.

For ordinary square-pixel footage, three bounded samples check for consistent black borders already embedded in the source. Only stable, sufficiently large picture rectangles are cropped; dark/ambiguous scenes, changing framing, and non-square-pixel sources retain their geometry. This conservative detector cannot promise removal of every authored border or make black footage colourful. Prior results, reviews, and saved selections are preserved. A changed transcript invalidates earlier results and stops further requests at the next window boundary; failed attempts retain the previous successful result.
- Candidate accept/reject reviews use optimistic revisions. Accepting a stale suggestion fails explicitly. Empty results are valid; unsupported quotes/times are discarded, and an entirely invalid result fails rather than becoming fabricated clips.
- The default model is configurable `gpt-6-luna`, which supports structured outputs through the [OpenAI Responses API](https://developers.openai.com/api/docs/models/gpt-6-luna). Default limits are 64 overlapping three-minute transcript windows, 2 MiB of combined transcript-window input, and 2,048 output tokens per request. These are usage limits, not a dollar guarantee or a validated quality target. There are no automatic retries of billable operations. Regeneration deliberately incurs new usage; retrying after editorial review failed can reuse completed discovery. The panel displays reported token usage for successful analyses.
- The provider uses a fixed HTTPS endpoint, verified TLS, no redirects or inherited proxies, bounded response bodies, strict JSON Schema, and `store: false`. Refusals, incomplete/malformed results, timeouts, access failures, and rate limits are explicit. Provider bodies, headers, and credentials are not copied into errors or logs.

The backend reads `OPENAI_API_KEY` from its process environment first, then from the project's ignored `backend/.env` file. A saved key is reused automatically on every API start. Only that backend file is read, variable interpolation is disabled, and its values are not copied into the process environment or frontend. Keys are excluded from settings representations, logs, and tracked source. `CLIPPING_HIGHLIGHT_MODEL` selects the model and `CLIPPING_HIGHLIGHT_MAX_WINDOWS` sets the request cap from 1 to 192. Transcription/export remain available without a key.

Routes: `GET /api/highlights/config`, `GET/POST /api/recordings/{id}/highlights`, `POST /api/highlights/{id}/cancel`, and `PATCH /api/highlight-candidates/{id}`. Generation requires the current transcription ID/revision, literal `remote_consent: true`, minimum/maximum whole seconds from 8 to 120, and optional `max_candidates` (1 to 20, default 10) and `regenerate` (default false). Review requests supply `review` and the expected candidate `revision`. The SQLite additions preserve existing recordings, exports, and selections.

## Using the workspace

1. Import an MP4, MOV, MKV, M4V, or WebM file. The app copies it into local storage and inspects the actual media; it does not modify your original.
2. Play or seek the source. Enter start/end seconds or use the playhead buttons. MP4 is recommended because browser playback support varies for other containers/codecs.
3. Choose **Fit full frame** to preserve the image with padding, or **Fill frame** to centre-crop. These are fixed framing modes, not subject tracking.
4. Open **Transcript & captions** and select **Transcribe recording**. Progress, cancellation, and retry are available. English is the supported language; silent/no-speech sources remain usable for manual exports.
5. Review the selected interval's words. Correct text or blank a word to omit it, then **Save corrections**. Original word timings stay fixed. “Review” identifies low model confidence, a review hint rather than a calibrated accuracy score.
6. Enable **Include captions** and choose lower, centre, or upper placement. The readable white/outline preset groups short phrases automatically. The editor shows text for review; the exported video is the authoritative burn-in preview.
7. **Save selection** stores boundaries, framing, and caption settings. Export also saves them before rendering. Save or explicitly discard pending changes before switching recordings. Conflicts from another window preserve your edits and require reloading the saved revision.
8. Export, review playback, and download. Dimensions, duration, codecs, and audio are verified. Captions are burned into the MP4; later transcript edits affect future exports while existing files retain their original snapshots.
9. Reopen the page to recover the selection, corrections, and history.

## Processing speed and diagnostics

New processing defaults use GPU speech recognition where available, up to three concurrent long-form AI windows, a reusable highlight pool, four render/filter threads and validated NVIDIA encoding. Processing remains bounded: one speech worker and one export worker per API process; supplied-video AI review/title requests remain sequential. Existing transcript and exact-export reuse remains in place.

- **Unused highlights:** each long-form window may propose up to five grounded moments; keep up to 20 ranked distinct candidates while exporting only the requested maximum. Find more clips can reuse eligible unused candidates without another API call. Pool identity includes transcript ID/revision, model, prompt/output policy, source range, duration/quality settings and extra AI instructions. Used source ranges and explicitly rejected moments are excluded. Changing these inputs invalidates the pool; explicit regeneration bypasses reuse. A remaining pool can return fewer than the requested maximum. Pools retain candidate metadata locally and survive restarts.
- **Parallel AI:** the default is three requests in flight, configurable from one to four. Every attempt is persisted before dispatch; request/time/input/token caps remain. Failure, cancellation or a changed transcript stops further dispatch and cancels pending local tasks, with no partial publication or automatic retry. Already-sent requests may still be billed. A pool can increase response tokens within the existing per-request cap; it does not add transcript windows.
- **Warm speech worker:** the same isolated process/model serves sequential sources, then the parent releases it after 120 idle seconds. Dispatch and expiry share a lock. Cancellation, worker/inference failure and application shutdown discard the process; subsequent explicit jobs recreate it. Original audio/ASR words and five-minute window alignment remain unchanged. Model files are still verified before every source. CPU fallback is reported in the saved transcript warning; actual `device` is persisted and copied on transcript cache reuse.
- **Rendering:** `auto` probes an actual NVIDIA encoder session before selecting NVENC. A compatible local encoder takes priority; unavailable hardware uses the existing libx264 veryfast CRF 20 path with a visible warning. NVENC uses H.264 preset p5, VBR CQ 20, AAC and the existing rendering, subtitle, overlay, geometry, duration and audio checks. CQ and CRF are different controls; judge visual quality on representative footage before publishing. A render that fails after selection is reported, without silently switching encoders or retrying. Probe results are cached for that binary version until backend restart.
- **Timings:** project results show persisted elapsed seconds for download, transcription, AI, visual analysis, rendering and thumbnails, plus actual speech/video backends and pool reuse. Times accumulate per stage in the latest run and include waits for shared workers; active stages appear when they finish. Resume starts a fresh timing set. Each successful export stores its own encoder, seconds and fallback warning, also shown in Clip editor. Older jobs without timing/device records show no invented measurements. These are observations, not estimates of time remaining.

## Transcription and caption contracts

- The pinned `small.en` model uses faster-whisper with automatic CUDA `int8_float16` selection and visible CPU `int8` fallback. Six CPU threads, beam size five, English word timestamps and voice activity detection remain the defaults. CUDA initialization includes a real encoder/decoder probe before any source words are emitted; explicit CUDA mode fails if initialization is unavailable. Speech recognition stays offline; optional highlight analysis sends only saved transcript text/timestamps to OpenAI after consent.
- One transcription runs at a time in a separate cancellable process, with a two-hour deadline and bounded results/logs. FFmpeg decodes temporary 16 kHz mono PCM to disk while preserving source offsets. Inference reads five-minute windows with two seconds of context instead of allocating a six-hour waveform. Temporary audio needs approximately 115 MB per source-hour, plus the normal disk reserve.
- Transcription and YouTube workers publish progress as atomic file snapshots. Publication and bounded snapshot reads retry Windows access/sharing/lock conflicts for at most 0.63 seconds. Windows CRT reads can report sharing conflicts as EACCES without a Windows error code; these reads receive the same bounded retry. Missing unpublished snapshots are allowed; malformed/oversized state and persistent access errors fail visibly. This retries only local snapshot I/O, never inference, API requests, or downloads. Transcription parent failures also save their traceback in `data/logs/transcription-{id}.log`, alongside worker diagnostics.
- Cache identity includes source bytes, pinned model files/revision, inference settings, FFmpeg, and relevant runtime versions. Same-recording retries retain corrections. Duplicate imports may reuse recognition but keep separate editorial changes. Changing clip boundaries reuses the saved transcript directly.
- Words use source-relative timestamps. Rendering intersects and rebases them to the clip, groups phrases, and neutralizes ASS control syntax. Text-only corrections retain word timing; optional manual timing corrections preserve original ASR intervals for restore. Partial boundary words are clamped. Phrases below ASS's 0.01-second precision fail visibly. Review names, unclear audio, and boundary synchronization before publishing.
- Transcript publication is transactional. Corrections use expected revisions and return 409 on conflict. Exports snapshot validated words/settings when accepted, so later changes cannot alter queued work. Restart marks interrupted jobs failed with a retry path and preserves completed results.
- Isolated words with zero-length or backward model timing are omitted rather than assigned invented timestamps. The saved transcript warning counts omissions and is exposed in project results and TikTok review. Non-finite/out-of-source timestamps and invalid overall output still fail. Review warned transcripts and rendered captions against the audio; omission does not establish recognition quality.
- This slice has no speaker diarization, translation, or forced alignment. Flow/Glow use existing word timings and cannot repair recognition errors. Speech recognition can mishear names, accents, music, and overlapping speakers; no speech may legitimately yield zero words. Six-hour throughput and broad real-world accuracy have not been established.

API additions: `GET/POST /api/recordings/{id}/transcription`, `GET /api/transcriptions/active`, `POST /api/transcriptions/{id}/cancel`, `GET/PATCH /api/transcriptions/{id}/words`, and `GET/PUT /api/recordings/{id}/draft`. Word reads accept an interval within the source, up to six hours. Corrections accept at most 100 word IDs and 48 characters per field; the UI batches at 50 to respect the body byte limit. Clip creation accepts optional `captions: {transcription_id, revision, position, preset}`; omitted `preset` retains Classic. Additive metadata schema version 2 preserves existing recording/export rows while adding saved selections and immutable caption snapshots.

Current bounds: 20 GiB per imported file by default (configurable from 1-100 GiB), six hours per source, 0.1 seconds up to the six-hour source bound per export, one import at a time, one export at a time, and a render timeout of ten minutes for up to two minutes of media, scaled proportionally up to two hours for longer exports. Uploads have a 30-second idle and 30-minute total timeout. Processing checks a 256 MiB free-disk reserve; exports are capped at 512 MiB. The API lists up to 100 rows per page; the interface loads older recordings and pages through 20 exports at a time. These are implementation limits, not measured throughput guarantees.

Inputs must have a measurable frame rate of at most 120 fps and supported dimensions of at most 7680 per side and 34 million pixels. HDR inputs are rejected until explicit tone mapping is available. Non-square pixels and rotation metadata are handled in the display geometry. Variable frame-rate sources retain variable timing; output duration is verified within a frame-based tolerance. Sources with unusual timestamps or browser-incompatible codecs may still require conversion to a conventional SDR MP4.

## Local storage and security

`data/` holds the SQLite database, copied sources, MP4 exports, cached thumbnails, and processing logs. Paths use generated IDs, not uploaded filenames. Playlists and arbitrary remote URLs are not accepted; the restricted YouTube/Twitch importer is the supported remote-source path. FFmpeg input protocols and formats are restricted to local media; uploads, downloads, previews, and exports have explicit bounds. Cross-origin browser requests and non-local hostnames, including forwarded hostnames, are rejected. Control requests have a small body limit and timeout. This process-level bounding is not an OS sandbox or a hard total-memory limit for FFmpeg.

Cliptric is a single-user application with a shared local library. The optional private HTTPS gateway protects remote access for the owner. It does not provide separate user libraries. Keep both application servers bound to loopback. Project/export deletion is available; source-recording and whole-installation erasure have no in-app interface.
