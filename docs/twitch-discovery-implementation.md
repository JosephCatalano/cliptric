# Cliptric Twitch Discovery and publishing automation

Implementation brief and handoff prompt. Copy everything below into a coding agent working at the Cliptric repository root, or ask it to implement this file in order.

## Prompt for the coding agent

Implement Twitch Discovery in the existing Cliptric application. A saved scan should discover clips from a streamer or game, import clips that the owner is authorized to reuse, create finished short videos using the existing editing pipeline, and dispatch them to selected connected accounts wherever the provider and Cliptric's approval contract permit it. Implement the workflow through its real UI and backend entry points. Carry the supported flow through to completion and document what requires real credentials, media, or provider review.

Read the shared coding preferences, repo `AGENTS.md`, relevant README sections and nested instructions. Check Git state and preserve existing changes. Load the project's shadcn, React, video processing and caption skills as applicable, and read the installed Next.js documentation before writing frontend code. Trace the real call paths before proposing new APIs. Start with the supplied-video batch workflow (`/projects/batch`), automatic presentation (`backend/presentation.py`), posting copy (`backend/social_copy.py`), connected accounts (`/connections`), batch publishing and Calendar (`backend/scheduling.py` and the existing provider adapters). Use current code as the reference for worker lifecycles, state and routes. Reuse the recording, project, transcript, preset, export and publishing models and services. Add only the Twitch adapter, discovery/automation state and orchestration needed to connect them. Keep existing Twitch VOD imports compatible.

### 1. Discover clips and save searches

- Add a Discover area with a Twitch view using the existing Cliptric design system. Accept a streamer login or canonical profile URL, a list of streamers, or a game/category picked by name. Resolve stable Twitch IDs. In this feature, streamer means whose broadcast the clip came from. Category results may span many broadcasters.
- Support Run now, saved searches, edit, clone, reusable scan settings, pause/resume, delete and run history. Default recurring scans to off. When enabled, run every 10 minutes by default with configurable cadence. Run on the local backend and expose the last run, next run, errors and queue state. State clearly that scans require the API to run and the computer to stay awake. Coalesce missed scans into one run when the service resumes. Use independent toggles for recurring discovery, automatic draft preparation and any permitted posting automation.
- Default to the previous 24 hours and 15 visible candidates. Support date presets and a custom range, a configurable result count up to 100, minimum views, duration, language and broadcaster filters. In v1, rank by Twitch views, with a recent option within the fetched candidates. Later add an optional views-per-age estimate, labeled as such, and a configurable content focus. Never label a score as a prediction of virality. Bound pagination, request time and total candidates, respect rate-limit headers, and surface when a scan is partial. Re-read Twitch discovery ordering, pagination and date-window semantics. [Twitch Clips API](https://dev.twitch.tv/docs/api/reference/clips)
- Show thumbnail, title, streamer, duration, views, creation time, source link, rank reason and eligibility. Use Twitch's official embed where allowed, with Open on Twitch as the fallback. Allow filters for previously reviewed and rejected items, plus batch review, hide and queue actions. Keep public discovery caching within the applicable Twitch terms, including expiry of covered IDs, thumbnails and metadata. Preserve per-run counts where permitted. [Twitch embed requirements](https://dev.twitch.tv/docs/embed/video-and-clips)

### 2. Authorize, import and deduplicate

- Use documented Helix endpoints. Keep Twitch OAuth and encrypted token storage in the backend. Validate identity and required scopes, and support disconnect and expiry. Public discovery and clip download are separate capabilities. For downloads, require valid broadcaster/editor access and group up to 10 IDs per request for the same broadcaster. Request short-lived URLs at dispatch. Never derive MP4 URLs from thumbnails or use undocumented endpoints or scraped sessions. [Twitch Clips API](https://dev.twitch.tv/docs/api/reference/clips)
- Record who has the rights to download, edit, retain, send to external AI and publish, with source scope and expiry as applicable. Enforce the applicable rights at each stage and stop pending work on revocation. Store only permitted provenance and history, support purge/takedown, and document how removals are handled. OAuth permission by itself gives no reuse rights. For unrelated public clips show discovery only, with a path to supply a separately authorized file using the existing batch editor. Confirm applicable Twitch terms before redistributing, sharing data with AI providers or enabling campaign use. [Twitch Developer Services Agreement](https://legal.twitch.com/en/legal/developer-agreement/)
- When automatic preparation is enabled, enqueue up to the top 15 eligible unseen clips per run within separate configurable import, daily, storage and AI budgets. Use a bounded backlog and worker concurrency. Continue through the configured candidate window when higher-ranked entries are duplicates or ineligible. Explain why a run imported fewer items. Capture scan settings and preset revisions at enqueue so edits apply to future runs.
- Claim work transactionally by canonical Twitch clip ID across all scans and restarts. Retain the minimum durable record for authorized imports as long as permitted, independent of draft deletion. Keep failed/downloaded/processed/dismissed states distinct. Retry confirmed transient failures with backoff while respecting pause, rights checks and limits. If only rendering failed, reuse the saved source and transcript. Where present, use broadcaster, VOD ID and overlapping source timestamps to flag likely duplicates for review. Distinct clip IDs with missing or ambiguous VOD timing can still contain the same moment.
- Download through the existing guarded media transport or equivalent shared controls. Verify every redirect and resolved address, stream bounded bytes into managed temporary storage, validate the completed media with the existing probe, and commit the recording once. Pass only local media to FFmpeg. Recover abandoned work and clean partial files without deleting shared recordings, transcripts or legitimate exports.

### 3. Produce editable, quality checked drafts

- Treat each Twitch clip as a supplied short recording. Default to one full-length draft per clip and reuse the existing batch pipeline, transcription and immutable export logic. Make additional trim or highlight selection optional. Use a saved project preset snapshot with caption style, headline, presentation and branding where supported. Generate local, timed speech captions when speech is available. For silent/gameplay clips, preserve the picture and audio and omit invented captions.
- Default to a 9:16 output. Use a reliable existing webcam split with webcam above and gameplay below when a source preset provides valid regions or existing presentation analysis can reliably identify them. Preserve aspect ratio and protect gameplay HUD, subtitles and important action. Expose Fit, Fill/crop and existing split variants. Any deliberate stretch must be an explicit preset choice. Prefer a centered full-picture layout on blur/padding when the webcam is absent or ambiguous. Keep the chosen layout, crop regions and reason visible. Use a suitable authorized portrait source as-is when reframing would damage its composition. Let reviewers open the result in the existing editor and correct framing and text.
- Reuse the title/headline and posting-copy services to create separate burned-in headlines, platform titles where supported, descriptions and hashtags. Apply the current prompt-settings and source-grounding contracts. Adapt copy through existing destination validation and presets. Require valid consent for each type of external sharing or charge before enqueueing an AI stage. Honor existing project consent contracts when creating each automation project and persist its grant and attempt identity. If consent or reliable evidence is missing, use a neutral local headline or leave copy for review per preset. Never replay an uncertain paid call implicitly.
- Add optional second-stage content ranking after the end-to-end path works. Reuse compatible bounded speech, audio and visual evidence. Report hook, payoff, standalone clarity and visual strength. Support visual-only highlights when authorized, with optional GTA tags such as chase, RP, fail or glitch. Keep download and analysis caps separate. If the existing multimodal services cannot assess short visual-only clips accurately, report that limit and keep metadata ranking usable.
- Mark exports ready only after the actual immutable MP4 passes existing media checks. Route missing copy, uncertain rights/layout, problematic content or invalid platform settings to an actionable review state. Preserve old exports and require fresh approval for changed media, account or posting settings.

### 4. Dispatch across connected platforms

- Support selecting one or more concrete accounts from YouTube, TikTok, Instagram, X and Facebook Page Reels through existing capabilities. Offer Select all eligible to snapshot the accounts currently selected, with a per-account readiness or blocker reason. Newly connected accounts require explicit inclusion. Revalidate saved account IDs, scopes, visibility, media limits, posting copy, rights and settings before dispatch. A revoked or disconnected account fails independently and is never silently replaced.
- Deliver batch approval and automatic dispatch first. On one review screen show intended posts with the exact immutable export, destination account, text, visibility, and relevant destination settings. Reuse existing batch publishing and Calendar dispatch so the user can approve once for multiple finalized posts and the worker sends each approved post automatically. Allow cancellation before handoff. Store the approval, export checksum and provider attempt references using the existing publishing path.
- Treat fully unattended publishing of future, unseen exports as a separate per-provider capability. Default each provider to review required. Cliptric currently requires approval of the exact export, account and settings. The requested exception is scoped to this new automation and may be implemented only where current official evidence supports the exact consent flow, app approval and account capability. Record that evidence and update the project contract for any supported exception. Require explicit, revocable enrollment for named accounts, allowable source and preset, visibility and posting limits. Implement and document a capability gate with review-required fallback. A saved scan, connected account, private visibility, draft upload or preset cannot substitute for applicable consent. TikTok's posting guidance requires express upload consent and has intended-use restrictions. YouTube requires prior specific and express consent for automated uploads. Avoid duplicate or substantially similar automated posts across multiple X accounts. For Instagram and Facebook verify applicable publishing permissions, account type, product approval and allowed interaction before enabling unattended behavior. [TikTok content sharing guidelines](https://developers.tiktok.com/docs/en/content-sharing-guidelines) · [YouTube developer policies](https://developers.google.com/youtube/terms/developer-policies) · [X automation rules](https://help.x.com/en/rules-and-policies/x-automation)
- Use the existing immutable post and duplicate protection contracts and a Twitch source-level check to prevent a normal rerender from reposting the same clip to the same destination. Preserve one result per account and display local queue, uploading, provider processing, published, failed and uncertain accurately. On a timeout after potential handoff, reconcile using stored provider IDs and never blindly resubmit. Let other destinations continue when one fails. Enforce independent posting caps and spacing, and give the user a way to pause dispatch. Explain any work already beyond the point where cancellation is possible.
