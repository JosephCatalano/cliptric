# Cliptric product and architecture review brief

This is the current-state brief for reviewing Cliptric, a local-first app that turns authorized recordings into editable clips, exports finished short videos, and distributes approved posts. The product priority is to improve the quality of finished clips before expanding into campaign management. The repository snapshot described here is `2938748` on `main`. The brief describes implemented workflows and identifies where real footage or provider verification is still needed.

## Prompt for the reviewing AI

Review this app as a product designer, a video editor, and a software architect. Recommend changes to the existing workflows, output quality, automation, and future feature set. Think through the experience of clipping a two-hour gaming VOD, finishing a batch of supplied shorts, and recurring discovery from an authorized Twitch channel.

- Identify where each user likely gets confused, spends time on repetitive work, or receives a weak result. For each finding, name the workflow, explain the cause, and propose a specific change. Distinguish a verified feature gap from a hypothesis that requires playback or observation.
- Rank the five highest-impact improvements. Give each an expected outcome, implementation effort, dependencies, and a measurable acceptance criterion. Include what can reuse the existing pipeline and what would require a new capability.
- Evaluate clip selection and pacing, caption accuracy and timing, webcam and gameplay framing, headline credibility, and reliability of bulk processing and publishing. Suggest a representative evaluation set and how to measure improvement over the current baseline.
- Identify which automations are safe and useful, which should produce reviewable drafts, and which depend on documented provider permissions or a different runtime. Preserve source rights, billing consent, immutable exports and exact-post approval boundaries. Assess whether the current fixed pipeline needs additional AI steps, local heuristics, or fewer controls before recommending a general-purpose agent framework.
- Propose a short roadmap, including one or two feature ideas beyond the obvious. Mark bigger bets and work to defer. Ask for additional evidence where it would materially change the recommendation. Do not treat a roadmap item, an editorial score, or a synthetic test as proof of real-world performance.

## Main user journeys

| Journey | What the user does | What Cliptric does |
| --- | --- | --- |
| Start from Home | Upload a video, paste a public YouTube or completed Twitch VOD link, reuse an imported recording, or reopen a project. | Streams uploads to disk. For links, checks metadata, starts a guarded download during setup, reports progress and prepares the source preview and filmstrip. |
| Find clips in long footage | Name the project, select the source search interval, choose clip duration and count, set style and optional AI instructions, then confirm creation. | Saves the job, transcribes locally, finds and reviews candidate moments using AI when authorized, validates their evidence and times, then renders the result set. The backend continues after navigating away. |
| Find more moments in the same VOD | Open a saved project and request up to the desired number of additional clips. | Reuses the downloaded recording, saved transcript and a compatible unused candidate pool where possible. Previously used source intervals stay excluded even after deleting a generated clip or project. |
| Finish supplied videos | In Batch editor, upload or reuse up to 15 videos. Choose multiple highlights, one AI keep/trim result, or Keep full length. | Processes each recording independently. Multiple mode can produce up to five edits per source and 75 in a batch. AI results can preserve the whole video when it works better. Keep full length can work without a selection-model call. |
| Discover Twitch clips | Create or clone a streamer/category scan, set filters, run it now or enable recurrence, then preview or select results. | Polls Twitch's clip metadata API, ranks candidates, records run history, and marks reviewed/hidden clips. With Twitch editor access and recorded reuse rights, manual or automatic preparation downloads eligible clips and passes each to the supplied-video workflow. |
| Review and refine | Open Projects, filter the gallery, accept/reject clips, open focused review, or edit an individual clip. | Keeps selection and mounted edits across filters. Applies validated bulk changes, rerenders affected outputs, and preserves earlier exports. |
| Use the manual Editor | Open a recording in Studio, mark source boundaries, transcribe or review existing words, adjust the draft, and export. | Can run local transcription, show word-level times, save corrections, and render directly. Optional Suggested moments loads an accepted AI interval into the editor for further changes. |
| Deliver clips | Download an individual video or a ZIP of selected/all ready clips. | Downloads completed artifacts. ZIPs include a manifest with source times, export IDs and exclusions, and are capped at 2 GiB. |
| Connect and publish | Connect a destination in Accounts. Choose exact clips, accounts, text, visibility, and any required disclosures. Approve an immediate or scheduled post, or approve a batch. | Uses the existing platform uploader for YouTube, TikTok, Instagram, X, or Facebook Page Reels. Tracks each job separately from local handoff through the provider outcome. |
| Monitor, recover or clean up | Use Projects, Editor and Publishing to inspect progress, resume work, cancel jobs, review past versions, reconcile uncertain posts, or delete records. | Reuses valid intermediates, preserves known outcomes and approval history, and prevents unsafe replays. Pending work and ambiguous external handoffs have different recovery rules. |

Navigation is Home, Discover, Projects, Editor, Publishing, Accounts and Settings. The shared workspace has light/dark themes, a compact navigation rail, and processing notices. Projects supports search across saved projects, status and sort filters, and grid/list views. Project results have clip filters, visible selection, batch actions and a focused review player.

## How a clip is made

`Source → probe → local transcript → select source interval → plan presentation and captions → render MP4 → review → export or approve a post`

1. **Import and probe.** The source is a local upload, an already imported recording, one public YouTube video or completed Twitch VOD, or an authorized Twitch Clip imported from Discover. Twitch VODs use the Video link flow. Twitch Clip discovery uses its own Helix adapter. The standard import limit is 20 GiB per file, configurable up to 100 GiB, with a six-hour source limit. Restricted, private, live or DRM-protected links are outside the shared URL importer. Network downloads check allowed destinations and redirects. FFmpeg processes local files.
2. **Transcribe.** Faster-whisper small.en produces English word timestamps on the machine, with CPU or CUDA support. Correcting a word's text or start/end produces a revised transcript and preserves the original recognition timing. Compatible repeats reuse saved inference. Spoken captions require usable speech. In the long-form workflow, an explicitly enabled visual analysis path can support silent footage.
3. **Select.** Long-form analysis uses timed speech from the user's selected range. Discovery windows propose moments, exact evidence and narrative notes. A separate final editorial pass compares a shortlist for setup, payoff and standalone clarity, and can repair boundaries or reject leads. The backend validates intervals, literal evidence or authorized frame references, and rejects duplication and overlap. In supplied-video mode, each source gets its own keep/trim or multiple-highlight decision, or is deliberately kept whole. A maximum clip count is a cap. Fewer results and empty results are valid.
4. **Compose.** The chosen source interval is preserved. Local presentation can propose a portrait crop, webcam/source split, following a single face, a cover frame, and compatible headline/caption placement. The user can adjust the layout, refine the cut, and stage local pacing or reframing suggestions. Enabled removals share a timing map across video, audio, captions, overlays and framing so each output stays synchronized.
5. **Render and check.** FFmpeg/libass renders a 1080 × 1920 H.264 MP4 with AAC when audio is present. Subtitles, titles and overlays are burned in. Local checks cover geometry, duration and expected audio. A completed export retains its exact transcript/word revision, layout, captions, text, and quality options. A new edit can create a new export while the earlier file and any approvals tied to it remain available.
6. **Review and deliver.** The user can compare source and export, trim, correct text, inspect the first-frame cover, use version history, download, or review a post. The preview approximates appearance. The exported MP4 is the reference for exact timing, line breaks and effects.

## AI roles and boundaries

The FastAPI backend orchestrates fixed stages. “Agents” here are task-specific model calls with limited inputs and validated outputs. They do not control the desktop, choose accounts, or decide to make external changes.

| Role | Inputs and output | When it runs |
| --- | --- | --- |
| Long-form discovery | Timed transcript windows, nearby chapter excerpts, content profile, project guidance, and optional sampled observations. Produces candidate leads and source-quoted narrative notes. | During authorized long-form analysis or explicit regeneration. A valid unused pool can avoid another request. |
| Long-form editorial review | Bounded candidate shortlist, transcript context, notes and any sampled observations. Returns reviewed candidates and supported boundaries. | After discovery when a shortlist exists. A retry after an editorial failure can reuse matching, completed discovery. |
| Sampled-frame description | With separate permission to share images, sends a bounded set of small timestamped stills to a vision model. Local acoustic measurements and scene cues can supplement the analysis. | Off by default. It samples moments and can miss fast action between frames. Full media stays local. |
| Supplied-video review | Saved timed speech for that recording. Returns a grounded keep/trim result or multiple distinct intervals and titles. | When the user chooses an AI review mode. Keep full length skips it. |
| Title generation | Bounded transcript text for the clip. Produces a potential title/headline. | Optional, including for full-length batches and automatically prepared Twitch clips when consent and the budget allow. Source-name fallback is available. |
| Posting copy | Speech retained in the chosen clip and project guidance. Produces an editable description and hashtag recommendations, plus alternatives. | Optional at creation or requested later. Sparse speech can require manual copy. Speech-affecting edits can mark copy stale before publishing. |
| Caption emphasis | Bounded words and token IDs. Suggests words to emphasize. | Explicit editor tool. The user reviews suggestions and saves the desired choices. |
| Local decision logic | Twitch metadata ranking, face and inset detection, crop safety, text structure, scene change, quiet gaps, timing and output validation. | Backend code runs these steps as configured. Face/inset detection establishes a possible layout. Editorial usefulness and actual gameplay meaning remain separate questions. |

OpenAI calls use structured outputs and backend credentials. The default text model in the current config is `gpt-6-luna`; sampled stills default to `gpt-4.1-mini`. Model IDs, input caps and concurrency are backend options. The UI's Settings page edits task prompts and shared project guidance. Prompt changes affect future requests and the applicable cache key while preserving saved outputs. Fixed application constraints still apply. AI requests record durable attempt markers, have budgets and timeouts, and avoid silently repeating uncertain billable work.

## Adjustable settings

- **Project source and scope.** Source range, content profile (Auto, Comedy, Podcast, Gaming, Interview or debate, Educational, Entertainment), Auto or manual clip duration bounds, clip count, optional sampled visual analysis, and free-text AI instructions. Supplied-video projects instead choose full length, single-result or multiple-result review, maximum outputs per source, and optional AI titles and posting copy.
- **Captions.** Enable/disable, presets including Flow and Glow, automatic or explicit placement, automatic phrase grouping or one to four words, letter case, font family/weight/size, colours, optional box, animation, manual emphasis words, optional AI emphasis suggestions, caption-only profanity replacement, and individual word text/timing corrections. Caption censoring leaves source audio intact. Reusable caption styles omit source-specific timing, text and emphasized words.
- **Video and presentation.** Auto layout, fit with blur fill, centre crop, adjustable portrait crop, webcam-above-source split, one-person Auto follow, and presentation profiles (Auto, Talking head, Podcast, Gameplay or Off). Edit webcam/source regions when needed. Auto layout chooses a composition for the clip and preserves the full picture when evidence is ambiguous. A separate presentation pass can suggest a cover and help place text. Both respect explicit overrides.
- **Editorial finishing.** Source in/out, title, opening headline text/position/toggle, opening cover source frame, timed text overlays, optional local quiet-gap/filler proposals, adjustable pause criteria, manual removals, audio cleanup and loudness normalization, and framing points. Detected removals and hook suggestions are reviewable before being applied. Saved selections and earlier outputs can be compared in Versions / undo.
- **Twitch scans.** One or more streamers or a game category, included/excluded broadcasters, age window or custom dates, view/duration/language filters, title-keyword topic presets, most views or post-sort of fetched clips by recency/views per hour of age, result count, cadence, separate automatic preparation toggle, import/AI/storage caps, an output preset, AI title/copy options and consent. Twitch defaults to 15 visible results from the last 24 hours, recurrence off, and an hourly cadence when enabled. The range starts at 10 minutes, so 15 minutes is supported. Preparation defaults to a maximum of 15 new imports per run and a 30-per-day budget. OAuth download access and rights to edit, retain, share transcripts and repost are distinct.
- **Publishing.** Select concrete connected accounts and platform-specific text, visibility, audience, disclosures and flags; schedule for a date/time or queue a batch. A batch supports up to 75 clips and 225 posts with one account per included platform and clip. Individual publishing can target other connected accounts, subject to platform and app limits.
- **Reusable configuration.** Save different generation presets for long-form and supplied-video setups, save caption styles, and clone Twitch scans. Browser setup recovery can restore editable settings using a saved source. Recovered/preset settings do not grant consent or silently generate media.
- **Owner configuration.** Provider credentials, text/vision model IDs, media sampling and request budgets, import limits, CPU/GPU selection, and render threads are backend settings. Account credentials stay on the backend; applicable OAuth tokens use Windows user-scoped encryption. The optional private HTTPS gateway lets the owner use the same local library remotely.

## What happens automatically

| Action | Behavior |
| --- | --- |
| Download from a supported video link | Starts during setup. Transcription, selection and rendering start after project creation. |
| Process a saved project | Backend handles transcription, the selected AI stages, local composition, rendering and thumbnails. A compatible transcript, saved selection or export can be reused. |
| Run a scheduled Twitch scan | Polls with the saved filters while the local API is up and the computer is awake. Missed scans coalesce after resuming. Public metadata and review flags expire after 24 hours. Recent run counts/outcomes are kept for 30 days. |
| Prepare newly eligible Twitch clips | With the separate preparation toggle and rights in place, queues eligible clips within budgets. Canonical IDs deduplicate imports. Overlapping offsets on the same VOD can flag a likely same moment. It prepares full-length shorts using the configured finishing options. Ranking is based on metadata. |
| Send an approved post | Dispatches at the scheduled time or when the approved batch can start. A platform's failure does not prevent other queued destinations from progressing. The upload and the provider's publication confirmation are separate states. |
| Post a future Twitch clip the user has never reviewed | Requires exact-export approval once the file exists. There is currently no standing approval for unseen future posts. |
| Mark a clip as Posted, accept a quality proposal, or publish a revised export | Requires a user action. Posted is a manual library flag, independent of provider status. A changed export has its own publishing approval. |

## Operational behavior and evidence

- The app is a single-user Next.js/TypeScript frontend and FastAPI/Python backend. SQLite holds recordings, transcript revisions, projects and items, export snapshots, job state and posting approvals. Source files, rendered files and previews are local. Some stages run through bounded workers, including one active speech process and one active export worker. The backend records elapsed stage times, actual device/encoder, AI usage, errors, and reuse. There is no managed always-on worker in the described setup.
- The key identities are source recording, transcript revision, project clip interval, export ID, and destination account ID. Exact approved posts also retain an export checksum, settings and provider attempt. Requests can survive retries and restarts without blindly reissuing uncertain generation or publishing. Disconnected destinations are not replaced with another account. Local deletion does not retract remote posts. General project deletion preserves shared sources, transcripts, prior versions and publishing records; authorized Twitch intake has a separate purge flow subject to dependency checks.
- Existing checks cover synthetic source-to-render behavior, metadata and OAuth/transport fixtures, scheduling/recovery, and a focused desktop browser test for Twitch scan editing. Real FFmpeg checks establish basic render properties. The representative editorial comparison, caption accuracy across noisy audio and gaming terms, crop stability on actual streams, and live Twitch OAuth and provider publishing are separate acceptance work. View counts and AI editorial scores do not establish how a published clip will perform.
- The broader product roadmap includes campaign rules, measured performance feedback, richer editing, and further automation. Existing topic filters are keyword rules over Twitch titles. Authorized multimodal ranking of Twitch discoveries, full-video semantic editing, multilingual transcription, analytics feedback and a general timeline editor are opportunities for review.
